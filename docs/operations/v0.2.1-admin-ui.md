## Reviewed Decisions

- Set document language to `ko`; remove redundant language from main.
- Use a page wrapper containing sibling `header > nav` and `main` landmarks.
  The header holds environment/session controls. Page headings/action bars use
  `div` or a named `section`; detail remains an `article`.
- Body/page wrapper has a `100dvh` minimum with a `100vh` fallback. Main fills
  the remaining height below the header, rather than adding another viewport
  height. Content/form/editor participates in the flex chain where appropriate;
  short viewports can scroll to reach controls. Do not stretch every child.
- Keep the 1024px shared content width and current horizontal gutters. Start
  main vertical padding at 32px on mobile and 48px on desktop. Account for it
  in the authoring viewport budget; retain the 128px editor minimum and
  body-only scrolling at normal heights. The header scrolls with the page.
- Use neutral bordered buttons for logout, navigation and neutral actions.
  Save/publish/republish use colored text with a white resting background and
  subtle hover, matching the existing danger-action pattern. Restore uses the
  same neutral treatment as Edit. Menu items retain borderless menu treatment.
- Apply hover only on hover-capable devices, retain visible keyboard focus,
  and suppress active-looking hover on disabled/inert controls.
- Center pagination as one content-sized group: previous arrow, the actual
  visible page numbers, then next arrow. Remove the fixed `w-45` reservation
  from `.page-numbers`; retain equal-size controls and symmetric gaps so a
  single `1` is centered and arrows sit beside it without unused number slots.
  Apply the same layout to normal and trash lists. Preserve five-page groups,
  disabled boundary arrows and hidden pagination for an empty scope.
- Move one-off layout, spacing, typography and responsive declarations into
  markup. Keep shared tokens, repeated control styles, accessibility defaults,
  and selectors needed to override generated Crepe DOM in CSS. Reuse a class
  only where it represents a repeated style; do not mechanically move all CSS
  or keep descendant selectors solely to style one page.
- Make each desktop row/mobile card navigate to detail from its non-menu
  area, in both normal and trash lists. Keep a real title anchor for keyboard
  use and native link behavior; do not wrap menu controls inside an anchor or
  replace table semantics with a button. Background click handling must ignore
  menu interactions, modified clicks and text selection. Title hover underline
  responds to the item hover, only on hover-capable devices; keyboard focus
  also identifies the link. Retain the title link for new-tab actions.
- Show dates as `yyyy-MM-dd HH:mm:ss` (for example, `2026-10-16 14:30:00`)
  using `Asia/Seoul`, independently of
  server/browser timezone. Reuse the formatter for list, trash, detail and
  recovery timestamps. Null remains `—`; API/storage and `time[datetime]`
  retain their UTC ISO values (`YYYY-MM-DDTHH:mm:ss.sssZ`). Display uses a
  zero-padded 24-hour clock, with no timezone suffix or milliseconds.
- Rename only new-post Save to `초안 생성`. Confirmed draft creation navigates
  to detail. Existing editing retains `저장`; creation-and-publication retains
  its existing partial-failure and uncertain-result recovery routes.
- Remove outer padding from the detail reading surface, including generated
  `.ProseMirror` padding, scoped to read-only content. Preserve paragraph,
  list and code indentation and the editing surface's 12px padding.

### Result Notice Policy

The planned policy for Task 2: confirmed success disappears after 5 seconds and can be
closed earlier. Pause its timer during pointer hover or focus within the notice;
start a fresh timer for each new result, even when the text repeats. Retain
failure/conflict/uncertain/warning notices until dismissed or superseded.
Closing a notice must not discard input, clear a conflict or enable an unsafe
retry. Read-only environment guidance and pending-operation status persist
while their conditions apply and have no close button or expiry.

| Confirmed operation | Proposed success text    |
| ------------------- | ------------------------ |
| Create draft        | `초안이 생성되었습니다.` |
| Save existing post  | `저장되었습니다.`        |
| Publish             | `발행되었습니다.`        |
| Republish           | `재발행되었습니다.`      |
| Archive             | `공개가 취소되었습니다.` |
| Soft delete         | `삭제되었습니다.`        |
| Restore from trash  | `복구되었습니다.`        |

Put each result sentence in the notice's bold summary/title (`message`,
rendered with `font-semibold`), not in its secondary details. Omit the post
title entirely from success notices; ordinary success needs no secondary text.
Reserve optional muted details for additional context or a required next step
on failures, conflicts or uncertain outcomes. The notice title means the
feedback summary, not the page heading or the post title.

Deletion remains soft deletion with the existing
confirmation. Preserve useful failure details and recovery actions. Never label
an observed result as confirmed success, and never show success for a save of
an older snapshot while visible input remains unsaved. A failed list refresh
after a confirmed operation reports the refresh problem without claiming that
the mutation failed. Verified logout still returns home; its failure retains
the existing retry guidance.

Use the same notice presentation in list, trash, detail and authoring. Carry a
confirmed success once across an internal Admin navigation when required
(draft creation, save or publication). Prefer a small notice context owned by
the mounted Admin layout; do not persist notices or encode a success claim in
a user-editable query parameter. Keep form-specific warnings and actionable
errors beside their existing controls.

## Global Constraints

- Preserve 767px responsive switching, table/card information and fixed
  pagination groups. Row navigation must respect pending-operation locks.
- Preserve mutation classification, revision checks, explicit confirmation,
  input retention and manual inspection of uncertain creation; no auto-create
  retries or extra create requests after partial publication failure.
- Preserve new-post recovery retention, explicit discard and lifecycle guards.
- Preserve strict CSP, nonce propagation, Markdown guards, read-only boundaries
  and logout's exclusive inert state across both new sibling landmarks.
- Keep UTC persistence/API contracts. This is a display-timezone change.
- Update authoritative design only after review. Do not duplicate historical
  acceptance evidence or mark this candidate physically verified in advance.

## Review Focus

1. Header separation must not leave logout usable during exclusive processing.
2. Long controls/notices and short viewports must not hide authoring controls.
3. Repeated results and navigation must not reuse a stale dismissal timer.
4. Menu clicks, keyboard input and text selection must not open detail by accident.
5. UTC day boundaries and non-Korean device zones must still display Korean time.
