### Approved browser-fetch diagnostic

Implementation follow-up (2026-10-13), branch
`codex/v0.2.1-logout-completion`: the application now clears recovery, requires
the observed manual logout redirect and protected API challenge before home
replacement, and retains failure/retry UI on cleanup, transport, timeout or
unexpected responses. Local explicitly skips Access. This is implementation
evidence only; post-deployment remote acceptance remains pending.

On the Preview default origin, an authenticated `fetch('/api/admin/posts',
{credentials: 'same-origin', redirect: 'manual', cache: 'no-store'})` returned
200/basic. `CF_Authorization` was present (value not recorded).

Fetching the official application logout endpoint with redirect `follow`
failed with `TypeError: Failed to fetch`, while the application cookie was
removed and a manual-redirect API read returned 0/opaqueredirect. A fetch error
therefore must not be treated as a reliable assertion that logout did nothing.

With redirect `manual`, logout returned 0/opaqueredirect. CDP observed the
application endpoint's 302 to the team Access login path with
`state=logged_out`. The browser did not follow that redirect. After 30 seconds,
temporarily restoring the same pre-logout application cookie for one read-only
API probe still returned 0/opaqueredirect, confirming rejection of that old
token in this test. The diagnostic cookie was deleted immediately afterward.
No token values were written to evidence and no authentication policy changed.

Recommended application mechanism: request the official same-origin logout
with credentials and manual redirects, require its observed opaque redirect,
then require a protected API probe with manual redirects to challenge access
before replacing location with the same origin's `/`. Neither an opaque logout
redirect alone nor a follow-mode fetch error proves completion. Failure,
timeout, an authenticated API response, or an unexpected response must retain
the error/retry UI. Do not follow the API challenge, since GitHub instant SSO
can establish a fresh session. Local skips Access revocation explicitly.
This establishes the observed Preview transport contract; product implementation
and post-implementation remote acceptance remain pending.
