`codex/v0.2.1-verified-logout`, based on `9684858`.

The [authoring plan](v0.2.1-authoring.md#task-5-verified-logout-and-same-environment-home-return)
requires actual Preview logout evidence before selecting the completion
mechanism. At preflight, the repository has only the Production Worker/D1
configuration, no shared `adminContext`, and an implementation that clears
recovery then navigates to `/cdn-cgi/access/logout`. It has no completion
verification, home return, or retry action. A separately provisioned Preview
URL has not yet been confirmed.

[Cloudflare's session management documentation](https://developers.cloudflare.com/cloudflare-one/access-controls/access-settings/session-management/)
was checked on 2026-10-12. Application-domain logout clears that domain's
authorization cookie and revokes the user's Access session across applications;
previously issued tokens stop being accepted after 20–30 seconds. This is
documentation evidence, not a test of this deployment. It does not establish
a browser-fetch completion contract or a supported home redirect parameter.

Before implementation, record the following on the isolated Preview origin:

- Worker origin, deployed Version ID/source SHA, browser, and Access protection
  for `/admin` and `/api/admin`; verify public `/` remains accessible.
- An authenticated baseline, then the logout request's status, redirect chain,
  final origin/URL, and browser-fetch behavior if considered for completion.
- Presence/removal of the application authorization cookie, recording only
  cookie metadata and never token values.
- Subsequent protected page and API access without automatic reauthentication,
  including the documented token-revocation delay.
- The supported completion signal and home-return mechanism, or the observed
  limitation requiring a revised design.

After that mechanism is established, implement and test cleanup failure/retry,
logout failure/retry, dirty-navigation cancellation/confirmation, Local's
absence of Access revocation, and same-origin home replacement. Mocked transport
tests prove failure handling only; remote authentication evidence remains
required.

Issue [#54](https://github.com/herokwon/blog/issues/54) still requires physical
mobile-keyboard evidence for Tasks 3–4. The user plans to perform that acceptance
after Task 5 implementation; this preflight does not mark it complete.
