# v0.2.2 Admin Status and List Flow

> Use `superpowers:executing-plans` for this approved implementation slice.

**Goal:** Apply the status/action wording and originating-screen workflow approved in [Issue #70](https://github.com/herokwon/blog/issues/70).

**Architecture:** Keep PostActions, PostList and the layout-owned transient notice.
Remove the list's publish-to-detail branch. Preserve APIs, revisions, soft deletion,
creation recovery, result classification and explicit confirmations.
Use bounded validated API reads to update mounted list/detail data without
allowing loader failures to replace the view. Read the corrected list page before
replacing its URL with `replaceState`, preserving history state. Disable Admin
main-content hover data preloads to avoid opening pre-mutation cached details.

**Status:** Implemented and locally verified on `codex/v0.2.2-admin-status-flow`.

## Review focus

- Row removal or page correction must retain operation feedback and release locks.
- Capture pre-mutation status for republication wording before reactive refresh.
- Confirmed mutation followed by failed refresh must identify refresh failure.
- Restore stays in trash/detail and preserves the post's prior publication state.
- New-post routes and uncertain/conflicting outcomes retain existing safeguards.

## Scope

Exact Korean copy and screen-by-screen behavior are authoritative in Issue #70.
No API/schema changes, shared-button redesign, cursor changes, list height changes,
authoring overflow changes, deployment or release promotion belong to this slice.

## Verification evidence

- Baseline: 82 workflow, 461 unit/component and 135 E2E tests passed.
- Seven new status/copy/list-flow E2E tests first failed against the baseline.
  Focused verification passed 47 cases after the refresh-failure correction,
  including list and detail failures, without mutation replay or lost feedback.
- Independent read-only review found one Important issue: SvelteKit revalidation
  can apply an error route instead of rejecting and can erase the operation
  result. Reproduced the failure, then replaced lifecycle revalidation with
  bounded API reads. No Critical or Minor issues were reported.
- Additional regression first failed when a hovered detail retained its old
  draft state after list publication. Admin main-content data preloads are
  disabled so subsequent navigation reads current state.
- The first integrated 8-worker E2E run passed 142/143; the existing desktop
  item-navigation test could not observe the opened trash Restore menu.
  It passed the baseline and focused runs. A serial full run then passed all
  143 cases. No product change or retry was added to suppress that failure.
- Final `pnpm test --workers=1` passed 82 workflow, 461 unit/component and
  144 E2E cases, including the production build and the preload regression.
  `pnpm check` reported zero errors/warnings; `pnpm lint` and
  `git diff --check` passed. The previously failed desktop menu case passed
  in both serial full runs; parallel timing stability remains separate.
- Inspected desktop/mobile list captures with the new archive filter/status.
  Preview, Production and physical-device acceptance were not performed.
